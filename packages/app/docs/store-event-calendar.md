### Store eligibility and activation gates

- **No entry is submission-ready on either store.** Apple excludes repetitive daily tasks and general awareness promotions; its Special Event badge calls for new content, features, or goods. Google excludes evergreen and routine promotions and requires new, noteworthy, user-facing content that runs in-app during the event and is easy to find on opening the app. A timed marketing message about an unchanged feature does not meet these requirements. The release/store owner must identify and verify a real qualifying in-app moment before reworking any draft for submission; none is identified here.
- The Daily screen displays a streak of won daily puzzles on consecutive UTC days. History separately counts any played local day. There is no event-specific tracker, reward, leaderboard, or special event state. Do not describe Infinity as a competition or Challenge mode as live multiplayer.
- The event artwork kit tracked in [issue #473](https://github.com/vitalyiegorov/suuudokuuu/issues/473) is pending. Artwork is an activation dependency for store submission, not for this planning calendar. Do not submit until the required platform artwork has been created, reviewed, localized as needed, and checked against current asset specs.
- Play promotional content is available to games, but featuring and deep-link options depend on account eligibility. Confirm those options in Play Console. On 2026-10-10, `suuudokuuu://play`, `suuudokuuu://daily`, `suuudokuuu://settings/themes`, and `suuudokuuu://history` opened Home, Daily challenge, Theme, and Statistics respectively in a Release E2E APK on Android 34. The corresponding Expo web export paths opened the same screens. History requires a completed puzzle before the player can select a game and use Replay. These route checks do not establish a qualifying event or verify the production iOS build. Test each full URL on a production build before using it in store metadata, including onboarding and the next user action.
- For each window, the release/store owner decides whether and which eligible event to request Play featuring for, within the remaining quarterly quotas of four broad-audience and two specific-audience requests. These dates are conditional planning targets, not five allocated requests; choose featuring when creating that event and submit it at least 14 days before start.

## Policy and route references

Rules checked 2026-10-10 against the current vendor guidance:

- [Apple In-App Events](https://developer.apple.com/app-store/in-app-events/) gives event name, short description, and long description limits of 30, 50, and 120 characters. [App Store Connect event guidance](https://developer.apple.com/help/app-store-connect/offer-in-app-events/offer-in-app-events/) allows at most 10 published events at once, event durations up to 31 days, and a discoverability date up to 14 days before start. The 14-day value is the maximum advance promotion window, not a mandatory submission lead time. This schedule uses that window where possible.
- [Google's content-quality guidance](https://support.google.com/googleplay/android-developer/answer/12929944) sets the 80-character tagline and 500-character description limits and the new, noteworthy in-app content requirements. [Play event creation guidance](https://support.google.com/googleplay/android-developer/answer/12932541) allows submission up to 60 days ahead, says review may take four days, limits events to four weeks, and requires a featuring-requested event to be submitted at least 14 days ahead. Featuring is selected when creating the event, cannot be added to an already submitted one, and is not guaranteed. Game quotas are four broad-audience and two specific-audience featuring requests per quarter.
- App route evidence: `brand.config.js` declares the `suuudokuuu` scheme and `app.config.js` uses it. `src/app/play.tsx` renders `HomeScreen`; `src/app/(tabs)/daily.tsx` renders `DailyScreen`; `src/app/settings/themes/index.tsx` is the theme route; `src/app/(tabs)/history.tsx` opens history, with difficulty selection before `src/app/history/[difficulty]/[completedAt].tsx` opens replay. No event-specific URL parameters exist.
